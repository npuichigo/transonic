Transonic · TTS Streaming Demo

A simulated TTS engine emits raw PCM; Transonic transcodes it to MP3 or WebM/Opus on the fly, and the browser plays the stream through MSE with a ~300 ms jitter buffer.

"Backpressure" reflects the gRPC FlowControlNotifications pushed over the WebSocket. As fast as possible floods the pipeline → ENOUGH_DATA (slow down); a realtime pace keeps it fed → NEED_DATA (send more); Bursty (TTS-like) alternates — each burst overruns the input buffer (ENOUGH_DATA) and each pause starves it (NEED_DATA), like a model emitting utterances with gaps.

"Transform first chunk" and "pipeline speed" are measured by the demo server on its gRPC connection to Transonic — if those are fast while playback start is slow, the delay is in the browser/network, not the service. Playback uses MSE with a ~300 ms jitter buffer; falls back to a plain <audio src> when the codec is not MSE-supported.
